## 2. 잘된 점 (Keep)

1. **함수 약속을 먼저 정했다.** 함수 이름, 받는 값, 돌려주는 값을 먼저 정했다. A는 가짜 데이터로 화면을 먼저 만들고, B는 함수를 만들어 서로 기다리지 않았다.
2. **모든 변경을 PR과 리뷰로 합쳤다.** 리뷰에서 `Closes` 번호가 빠진 것 같은 실수를 잡았다. main 보호 규칙 덕분에 main에서 실수로 작업한 코드도 바로 들어가지 않았다.
3. **계산 로직을 순수 함수와 테스트로 분리했다.** 인원 세기와 추천 시간을 화면 없이 테스트했다. CI가 PR마다 lint · test · build를 자동으로 확인해 줬다.

## 3. 아쉬운 점 (Problem)

1. **일정이 이틀 밀렸다.** 화면 설계서 확정이 늦었고, PR 리뷰를 기다리는 시간이 길었다.
2. **디자인을 마지막에 몰아서 했다.** 같은 파일(MeetingPage.jsx)을 둘이 동시에 고쳐 충돌이 났다.
3. **Git 기본 실수로 시간을 썼다.** 브랜치 확인 없이 작업하기, 커밋 전 브랜치 이동하기, 저장 안 한 파일로 헤매기 같은 일이 있었다.
