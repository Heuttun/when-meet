# 언제모여 요구사항 정의서

| 항목 | 내용 |
| --- | --- |
| 문서 목적 | 만들 기능을 빠짐없이 정의하고, 개발이 끝났는지 판단하는 기준으로 사용 |
| 작성 | 강경태 (A), 김가현 (B) |
| 작성일 | 2026.10.09 |
| 관련 문서 | [기획서](planning.md) · [화면 설계서](screens.md) · [ERD·테이블 설계서](erd.md) |

## 읽는 법

- **ID 체계:** 기능은 `F-01`, 그 기능의 세부 요구사항은 `F-01-1`, `F-01-2`처럼 번호를 붙입니다. 비기능 요구사항은 `NF-01`입니다.
- **우선순위:** `필수`는 7일 안에 반드시 완성합니다. `선택`은 4일차까지 필수 기능이 끝났을 때만 진행합니다.
- **GitHub Issue 제목**에 ID를 붙여 요구사항과 실제 작업을 연결합니다. 예: `[F-03] 시간표 그리드`

## 1. 기능 요구사항

### F-01 모임 만들기 `필수`

모임장이 제목, 후보 날짜, 시간 범위를 입력해 새 모임을 만듭니다.

| ID | 요구사항 | 담당 |
| --- | --- | --- |
| F-01-1 | 모임 제목을 입력할 수 있다 | A |
| F-01-2 | 날짜를 골라 후보 날짜 목록에 추가하고, 목록에서 개별 삭제할 수 있다 | A |
| F-01-3 | 시작 시각과 끝 시각을 1시간 단위로 고를 수 있다 (기본값 09시 ~ 22시) | A |
| F-01-4 | 입력값이 규칙(3장)에 맞지 않으면 만들기 버튼을 눌렀을 때 이유를 안내하고 저장하지 않는다 | A |
| F-01-5 | 만들기를 누르면 모임이 저장되고 고유 id를 돌려받는다 (`createMeeting`) | B |
| F-01-6 | 저장 중에는 버튼이 "만드는 중..."으로 바뀌고 다시 누를 수 없다 | A |
| F-01-7 | 저장에 성공하면 `/m/모임id` 페이지로 이동한다 | A |

**완료 조건**
- [ ] 제목·날짜 2개·시간 범위를 넣고 만들기를 누르면 `/m/모임id`로 이동하고, Supabase `meetings` 테이블에 1행이 생긴다
- [ ] 제목이 비어 있으면 "모임 제목을 입력해 주세요" 안내가 뜨고 저장되지 않는다

### F-02 링크로 모임 접속 `필수`

| ID | 요구사항 | 담당 |
| --- | --- | --- |
| F-02-1 | `/m/모임id` 주소로 접속하면 그 모임의 제목·날짜·시간 범위를 불러온다 (`getMeeting`) | B |
| F-02-2 | 불러오는 동안 "불러오는 중..."을 표시한다 | A |
| F-02-3 | 없는 모임 id면 "존재하지 않는 모임이에요" 안내와 첫 화면으로 가는 버튼을 보여 준다 | A |
| F-02-4 | 이 주소에서 새로고침해도 페이지가 정상으로 열린다 (배포 환경 포함) | B |

**완료 조건**
- [ ] 배포 주소의 `/m/모임id`를 새 탭에서 열어도, 새로고침해도 모임 정보가 보인다
- [ ] `/m/없는id`로 접속하면 안내 문구가 보인다

### F-03 내 시간 선택 `필수`

| ID | 요구사항 | 담당 |
| --- | --- | --- |
| F-03-1 | 이름을 입력하는 칸이 있다 | A |
| F-03-2 | 날짜(가로) × 30분 단위 시각(세로) 표를 보여 준다 | A |
| F-03-3 | 칸을 누르면 선택, 다시 누르면 해제된다. 선택된 칸은 메인 색으로 칠한다 | A |
| F-03-4 | 표의 칸 수는 모임의 날짜 수 × 시간 범위로 정해진다 (3.2 참고) | A |

**완료 조건**
- [ ] 날짜 3개, 18시~22시 모임에서 표가 3열 × 8행(18:00~21:30)으로 보인다
- [ ] 같은 칸을 두 번 누르면 원래대로 돌아온다

### F-04 선택 저장 `필수`

| ID | 요구사항 | 담당 |
| --- | --- | --- |
| F-04-1 | 저장 버튼을 누르면 이름과 선택한 칸 목록이 저장된다 (`saveAvailability`) | B |
| F-04-2 | 이름이 비어 있으면 저장 버튼이 비활성화된다 | A |
| F-04-3 | 같은 모임에서 같은 이름으로 다시 저장하면 새로 추가하지 않고 덮어쓴다 | B |
| F-04-4 | 이미 저장한 이름을 입력하면 그 사람의 기존 선택을 불러와 표에 칠한다 (`getMyAvailability`) | A·B |
| F-04-5 | 저장 성공 시 "저장됐어요", 실패 시 "저장하지 못했어요. 다시 시도해 주세요"를 보여 준다 | A |

**완료 조건**
- [ ] 저장 후 `participants` 테이블에 1행이 생기고, 같은 이름으로 다시 저장해도 행 수가 늘지 않는다
- [ ] 다른 기기에서 같은 이름을 입력하면 이전에 고른 칸이 칠해져 있다

### F-05 결과 히트맵 `필수`

| ID | 요구사항 | 담당 |
| --- | --- | --- |
| F-05-1 | 참여자 수와 이름 목록을 보여 준다 (`getParticipants`) | A·B |
| F-05-2 | 칸마다 가능한 인원 수를 계산한다 (`countBySlot`) | B |
| F-05-3 | 가능 인원 ÷ 전체 참여자 비율만큼 진하게 칠한다. 0명은 빈 칸, 전원 가능은 가장 진한 색 + 굵은 테두리 | A |
| F-05-4 | 표 아래에 "0명 ~ N명" 범례를 보여 준다 | A |
| F-05-5 | 새로고침 버튼으로 최신 결과를 다시 불러온다. 내가 저장하면 자동으로 다시 불러온다 | A |

**완료 조건**
- [ ] 두 브라우저에서 다른 이름으로 저장하면, 두 사람이 겹친 칸이 한 사람만 고른 칸보다 진하다
- [ ] `countBySlot` 테스트(참여자 0명 / 1명 / 3명 겹침)가 모두 통과한다

## 2. 비기능 요구사항

| ID | 구분 | 요구사항 | 확인 방법 |
| --- | --- | --- | --- |
| NF-01 | 사용성 | 처음 들어온 사람이 설명 없이 3분 안에 자기 시간을 저장할 수 있다 | 5일차 사용자 테스트에서 시간 재기 |
| NF-02 | 사용성 | 회원가입·로그인 없이 링크와 이름만으로 쓸 수 있다 | 시크릿 창에서 처음부터 사용해 보기 |
| NF-03 | 호환성 | 최신 Chrome, Safari, Samsung Internet에서 동작한다 | PC Chrome, 휴대폰 브라우저에서 확인 |
| NF-04 | 성능 | 참여자 20명인 모임의 결과가 1초 안에 보인다 | 테스트 데이터 20명 넣고 확인 |
| NF-05 | 보안 | Supabase 키는 `.env.local`에만 두고 레포에 올리지 않는다 | 레포 파일·커밋 기록 검색 |
| NF-06 | 보안 | 누구나 모임·참여자를 조회·추가·수정할 수 있지만 삭제는 할 수 없다 (RLS 정책) | Supabase Policies 확인 |
| NF-07 | 품질 | 모든 PR은 자동 검사(린트·테스트·빌드)를 통과하고 팀원 1명의 승인을 받은 뒤 합친다 | GitHub PR 기록 |
| NF-08 | 접근성 | 히트맵은 색만으로 구분하지 않고, 칸에 인원 수나 범례로 숫자를 함께 제공한다 | 결과 화면 확인 |

## 3. 입력값과 데이터 규칙

### 3.1 입력값 규칙

| 입력 | 규칙 | 어겼을 때 안내 |
| --- | --- | --- |
| 모임 제목 | 앞뒤 공백 제거 후 1~30자 | "모임 제목을 입력해 주세요" / "30자 이내로 입력해 주세요" |
| 후보 날짜 | 1~7개, 같은 날짜 중복 불가, 오늘 이전 날짜 불가 | "날짜를 하나 이상 추가해 주세요" / "이미 추가한 날짜예요" |
| 시간 범위 | 시작 < 끝, 0시 ~ 24시 | "끝 시각은 시작 시각보다 늦어야 해요" |
| 참여자 이름 | 앞뒤 공백 제거 후 1~10자 | 저장 버튼 비활성화 / "10자 이내로 입력해 주세요" |
| 선택한 칸 | 0개도 저장 가능 (그 사람은 모든 시간이 안 된다는 뜻) | — |

### 3.2 데이터 규칙

| 규칙 | 내용 |
| --- | --- |
| 칸 표현 | 칸 하나는 `"날짜_시각"` 문자열. 예: `"2026-10-13_19:30"` |
| 칸 단위 | 30분. 끝 시각은 포함하지 않음. 18시~22시면 18:00, 18:30, …, 21:30 (8칸) |
| 같은 사람 판단 | 같은 모임 안에서 앞뒤 공백을 제거한 이름이 같으면 같은 사람 |
| 모임 id | 추측하기 어려운 무작위 값(uuid)을 사용해 다른 모임 주소를 짐작할 수 없게 함 |
